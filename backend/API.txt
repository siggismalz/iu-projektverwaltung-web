API-VERTRAG DES LOKALEN LEHRPROTOTYPS
Stand 05.11.2026
Basis: http://127.0.0.1:8080

Authentifizierung: serverseitige Session. GET /api/csrf auch anonym abrufen; Response {token,headerName}. Bei POST/PUT/DELETE Token im angegebenen Header mitsenden und Session-Cookie beibehalten. Nach erfolgreichem Login und Logout CSRF erneut abrufen, weil Spring Security den alten Token entfernt. CSRF-Repository: Spring-Standard HttpSessionCsrfTokenRepository, maskierte Tokens mit BREACH-Schutz.

POST /api/login: form-urlencoded username,password; 200 {message} oder 401 {message}. Kein eigener Logincontroller: Spring-Security-Filter verwaltet Authentication, Sessionfixation und Contextspeicherung.
POST /api/logout: gueltiger CSRF-Header; 200 {message}, Session invalidiert und JSESSIONID geloescht.
GET /api/session: {id,username,displayName,role,tenantName}; ohne Session 401.

Rollenwerte: ADMIN, LEAD, MEMBER.
GET /api/users: [{id,username,displayName,role}], internes Namensverzeichnis ausschliesslich des eigenen Mandanten, lesbar fuer alle angemeldeten Rollen.
POST /api/users: {username,displayName,password,role}; nur ADMIN; 201 UserView. Mandant serverseitig vom angemeldeten ADMIN. Benutzername global eindeutig und auf Kleinbuchstaben normalisiert. Passwort 8-72 Zeichen sowie maximal72 UTF-8-Bytes; BCrypt. Rolle und Passwort werden nie als frei gebundene Entitaet uebernommen.
PUT /api/users/{id}/role: {role}; nur ADMIN innerhalb des eigenen Mandanten; 200 UserView. Letzter ADMIN des Mandanten darf nicht herabgestuft werden (409).

GET /api/projects: [{id,name,description,archived,memberIds,memberNames,totalTasks,doneTasks,progress}]. ADMIN sieht alle Projekte des eigenen Mandanten; LEAD/MEMBER nur Projekte mit eigener Mitgliedschaft.
POST /api/projects: {name,description,memberIds}; 201 ProjectView; nur ADMIN/LEAD. LEAD wird selbst als Mitglied ergaenzt. Neue Projekte sind aktiv.
PUT /api/projects/{id}: {name,description,memberIds,archived}; 200 ProjectView; ADMIN tenantweit oder LEAD als Projektmitglied. LEAD bleibt selbst Mitglied. Entfernen einer Person mit bestehenden zugewiesenen Aufgaben wird mit409 abgelehnt; vorher neu zuordnen. Projekte koennen archiviert und wieder aktiviert werden.
DELETE /api/projects/{id}: 204; gleiche Berechtigung wie PUT, entfernt auch Projektaufgaben. Die UI verwendet Archivieren statt Loeschen.

GET /api/projects/{id}/tasks: [{id,title,description,status,assigneeId,assigneeName,projectId}]. Gleiche Leseberechtigung wie Projekt.
POST /api/projects/{id}/tasks: {title,description,status,assigneeId}; 201 TaskView.
PUT /api/tasks/{id}: gleicher TaskInput; 200 TaskView.
DELETE /api/tasks/{id}: 204.
Alle drei Aufgaben-Schreiboperationen: ADMIN tenantweit, sonst eigene Projektmitgliedschaft erforderlich. Archivierte Projekte liefern409. assigneeId darf null sein, sonst Person aus eigenem Mandanten und Projektmitgliedschaft erforderlich. Statuswerte OPEN, IN_PROGRESS, DONE. Fortschritt = gerundeter Prozentwert erledigter Aufgaben, bei0 Aufgaben0 Prozent.

Fehler aus fachlichen Pruefungen, Validation und Security als JSON {message}. Projektfremder Zugriff403; fremder Mandant/nicht vorhandene Datensatz-ID404, um dessen Existenz nicht offenzulegen. Ungueltige Eingaben400, Konflikte409. BeanValidation fuer Pflichtfelder und maximale Laengen; unbekannte JSON-Felder werden abgelehnt. Niemals Tenant-ID aus JSON, URL oder Header als vertrauenswuerdige Autorisierung nutzen.

Persistenz: Tabellen tenants, app_users, projects, project_members, tasks; JPA/Hibernate; Fremdschluessel. Schemaentwicklung fuer Lehrprototyp ddl-auto=update. Datenbankdatei relativ zum Backend-Arbeitsordner ./daten/projektverwaltung.mv.db. Start/Rechte/Dateifreigabe sind fuer lokalen Betrieb ausgelegt; kein Produktiv- oder Lastnachweis.

Demo: alle Kennwoerter Demo2026!, nur synthetische Daten.
Hauptmandant Muster IT GmbH: admin=ADMIN, leitung=LEAD, mitarbeiter=MEMBER.
Zweiter Demomandant: fremd=ADMIN (bewusst starke Rolle, trotzdem kein Zugriff auf Hauptmandanten).
Projekte: Intranet-Relaunch (leitung+mitarbeiter,3 Aufgaben), Kundenportal (leitung,2 Aufgaben), Fremdes Projekt (fremd,1 Aufgabe). Seed nur bei leerer Mandantentabelle, keine Ueberschreibung beim Neustart.

Sicherheit: Bindung127.0.0.1:8080; Session-Cookie HttpOnly und SameSite=Lax;30Minuten Sessiontimeout; SpringCSRF aktiv; keine H2-Webkonsole, kein offenesCORS, kein HTTP-Basic. Lokales HTTP setzt absichtlich kein Secure-Cookie; fuer echten Betrieb sind HTTPS, sichere Secrets/Konten, Datenbankbetrieb, Backup, Migration und weitere Haertung erforderlich.
